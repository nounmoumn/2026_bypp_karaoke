# BYPP 구현 계획 — 다음 작업에서 바로 실행하기

> 제품·데이터·API의 기준은 [기획 v3](../instant_jpop_karaoke_web_spec.md)다. [Final Spec](../instant_jpop_karaoke_codex_final_spec.md)의 키·프리셋·Phone 출력 요구를 포함한다. 마이크는 스피커 옆에 두는 독립적인 노래방 마이크이며 웹 입력 기능은 구현하지 않는다.

현재 상태는 **기획만 완료**다. 아래 체크박스는 구현·실측 결과를 확보한 뒤 체크한다. 18시간은 원본 기획에서 가져온 가정이며 공식 대회 시간으로 확인된 값이 아니다.

## 1. 시작 전에 정할 것

| 항목 | 현재 상태 | 답이 없을 때의 기본값 |
|---|---|---|
| 공식 개발 시간·제출 형식 | 미확인 | 18시간 예산, 로컬 웹앱 시연 |
| 심사 기준·발표 시간 | 미확인 | 개인 문제 해결과 실제 사용, 약 3분 발표 |
| 인원 | 미확인 | 1인, 순차 작업 |
| CPU/GPU/RAM·남은 디스크 | 미측정 | 첫 단계에서 실제 조회 |
| Python·FFmpeg·모델 설치 환경 | 미검증 | smoke test 후 성공한 환경 고정 |
| 공개 접속 의무 | 미확인 | localhost, 단일 사용자 |
| 사용할 곡·가사 | 미제공 | 사용 가능한 샘플 3개를 준비하는 것이 선행 조건 |
| GPU 서비스 비용 상한 | 미정 | 유료 서비스를 필수 경로에 넣지 않음 |
| 시연 폰·노래방 마이크 | 장비 미확인 | 폰 스피커 옆에 독립 마이크를 두고 소리를 받음. 기기 간 연결 없음 |
| 폰 접속 경로 | 미검증 | 폰에서 웹 반주를 재생할 수 있는 LAN/HTTPS 경로 |
| pitch 엔진 | 미검증 | rubberband 포함 FFmpeg 빌드 확인 |

첫 단계에서 공식 안내가 있으면 일정·제출 조건만 확인해 계획에 반영한다. 안내가 없다고 전체 작업을 멈추지 않는다. 다만 오디오·가사가 없으면 실제 정렬 PoC는 완료 처리할 수 없다. 그동안 설치와 합성 fixture 기반 플레이어를 준비하고, 실제 검증 미완료를 분명히 남긴다.

개인 문제 기록은 다음 네 줄로 충분하다.

```text
부르고 싶은 곡 / 버전:
최근 부르려다 막힌 상황:
기존에 시도한 방법과 소요 시간:
이 도구로 가장 먼저 하고 싶은 일:
```

## 2. 18시간 기본 시간표

모든 시간은 작업 시작 후 누적 시간이다. 모델 다운로드·환경 설정도 예산에 포함한다. 대기 시간을 빼서 일정이 맞았다고 하지 않는다.

| 구간 | 작업 | 남겨야 할 결과 | 통과 조건 |
|---|---|---|---|
| 0~1h | 환경·자료·평가 기준 준비 | 환경 기록, 3개 구간, 기준 줄 경계 | FFmpeg/rubberband·모델 로드 확인 |
| 1~3h | 실제 분리·정렬·pitch PoC | 자동 결과, 경계 비교, 구현 모드 | v3 게이트 평가·키 ±5 템포 보존 확인 |
| 3~5h | 작업 API·계약·worker 골격 | DB, 상태 API, 합성 fixture, 실패 복구 | 새로고침·worker 중단 후 상태 일관성 |
| 5~7h | fixture 기반 플레이어 | 재생·탐색·현재/다음 줄·간주 | 시각 기준 동기화, 합성 60초 시연 |
| 7~8h | 일본어 읽기·한글 독음 | 변환 모듈, 예외 표시, 줄 매핑 | 기본 사례·수정 fallback 확인 |
| 8~10h | 실제 파이프라인 연결 | 업로드→worker→결과→플레이어 | 캐시 아닌 새 입력으로 끝까지 실행 |
| 10~12h | 필수 키·프리셋 | variant API·캐시·전환 UI | 음정 변경·같은 위치 복원·실패 롤백 |
| 12~13h | Phone·가사 모드 | 출력 프로필·가사 모드 | 스피커 옆 노래방 마이크로 실제 청취 |
| 13~14h | 최소 수정·재방문 | 독음·시간 수정, 저장, 최근 결과 | 시간 없는 줄 복구·설정 다시 열기 |
| 14~16h | 전체 곡·오류·브라우저 검증 | 체크리스트, 측정표, 결함 수정 | P0 완료 기준 통과 |
| 16~18h | 시연 패키지·발표·버퍼 | 오프라인 결과, 실행 안내, 녹화 | 재시작 후 리허설 성공 |

필수 기능이 늘어 기존 18시간 계획보다 위험도가 높다. 이 표는 공격적인 목표이며 보장 일정이 아니다. 독음·수정 UI 시간을 줄이는 대신 파형 편집기 없이 최소 입력 폼을 사용한다. 기존 코드가 없는 상태에서 시간이 부족하면 자동 정렬 정밀도·Guide·배경을 줄인다. 키·프리셋·Phone을 빠뜨린 상태로 P0 완료라고 하지 않는다. 14시간 이후에는 새 기능보다 수정·시연 안정성을 우선한다.

### 시간에 따른 중단 규칙

- 1시간에 설치도 통과하지 못하면 남은 PoC 예산에서 환경 해결 시간을 제한하고 원인을 기록한다. 새 인프라를 즉흥적으로 늘리지 않는다.
- 3시간에 자동 정렬이 안 되면 반자동 모드로 결정한다. 세부 alignment 모델 탐색을 계속하지 않는다.
- 7시간에 합성 fixture 재생이 안 되면 sweep을 내려놓고 줄 전환·탐색부터 완성한다.
- 10시간에 실제 업로드 E2E가 안 되면 모든 P1/P2를 제거한다.
- 12시간에 키 전환이 안 되면 렌더/캐시 경로와 엔진 문제를 해결한다. 키 기능을 임의로 후순위로 내리지 않는다.
- 14시간에 P0가 남아 있으면 전체 곡 자동화 성능을 약속하지 않고 검증된 입력 범위를 명시한다.
- 16시간 이후 새 모델·새 배포 구조·새 UI 라이브러리를 도입하지 않는다.

## 3. 구현 티켓과 의존 관계

### T01 — 환경과 PoC (0~3h)

**목적:** 가장 위험한 가창 정렬을 먼저 검증한다.

- [x] CPU/GPU/VRAM/RAM, OS, 디스크 여유 기록. CPU 전용 환경이며 별도 GPU/VRAM은 확인되지 않았다.
- [x] Python·FFmpeg·PyTorch·분리/정렬 패키지 설치와 모델 로드 확인.
- [x] rubberband 필터 실행, 합성 테스트음으로 ±5반음 주파수 비율·템포·시작 지연 점검.
- [ ] 실제 폰 접속 경로·브라우저 확인. 노래방 마이크를 폰에 연결하지 않고 스피커 옆에 두는 시연 준비.
- [ ] 성공한 버전, 가중치 revision, 실행 명령 기록.
- [ ] A/B/C 구간과 해당 가사 준비. 구간 시작 offset 기록.
- [ ] 평가할 최소 20줄의 시작·끝을 직접 표기.
- [ ] 분리한 MR을 실제로 듣고 잔류 보컬·악기 손상·클리핑 기록.
- [ ] 거친 구간 매칭 → 제공 가사 재정렬 → 경계 평가.
- [ ] 자동/혼합/수동 모드와 선택 이유 기록.

산출물: `docs/poc_results.md`, 로컬 `data/poc/`의 모델 출력·측정 기록. 테스트용 음악·가사 원문은 Git에 기본 포함하지 않는다.

통과는 “라이브러리가 실행됨”이 아니라 실제 경계 비교까지다. 자료 부족·설치 실패는 미검증 또는 실패로 남긴다. 임시 수동 시각을 자동 추론 결과로 섞지 않는다.

### T02 — 계약·API·worker (3~5h)

의존: T01 모드 결정. 모델 실행 없이도 계약·상태 구현 가능.

- [ ] Pydantic 결과 모델, 작업 상태·단계·오류 코드 정의.
- [ ] SQLite jobs 테이블: id, status, stage, created/updated, error, input hash, revision.
- [ ] 업로드 검사, 생성·조회·결과·수정·재시도·삭제 API.
- [ ] variant 요청·상태·자산 계약, -5..+5 검증, 렌더 중복 방지.
- [ ] playbackPreferences·keyPresets 저장과 가사 수정의 revision 공유.
- [ ] 단일 worker만 실행, queued → running 작업 획득을 트랜잭션으로 처리.
- [ ] 진행 중 재시도/삭제 거절, 종료된 작업만 허용.
- [ ] worker 중단 뒤 running → failed 복구.
- [ ] 임시 결과 검증 후 게시. API 응답에 OS 내부 경로를 노출하지 않음.
- [ ] 모델과 무관한 60초 합성 fixture를 계약 검증에 사용.

fixture에는 시작 전 무음, 두 줄, 긴 간주, 마지막 줄, 미정렬 줄, 반복 문장·서로 다른 ID를 넣는다. 합성/수동 fixture임을 메타데이터 또는 개발 문서에 표시한다.

### T03 — 플레이어 (5~7h)

의존: T02 결과 계약. 실제 모델 정확도와 별개로 구현한다.

- [ ] 단일 audio와 currentTime 기반 현재 줄 계산.
- [ ] 재생·정지·앞뒤 탐색·곡 끝·간주 처리.
- [ ] 검은 배경·한글 기본, 한글/일본어+한글/일본어 전환, 다음 줄 예고.
- [ ] audio 재생 성공 후 UI 상태 반영. play 거부 시 버튼·안내 제공.
- [ ] 폰트 로딩·줄바꿈 후에도 텍스트가 잘리지 않음.
- [ ] null 타이밍은 동기화 목록에서 제외하고 수정 필요 표시.

여기서 만드는 것은 기본 줄 강조다. 모라 sweep·멋진 배경 효과로 계약/재생 버그를 가리지 않는다.

### T04 — 읽기와 한글 변환 (7~8h)

- [ ] 원문·줄 순서·반복 ID 보존.
- [ ] 읽기·품사를 추출하고 조사 발음 처리.
- [ ] 요음·촉음·ん·장음의 내부 정보를 보존.
- [ ] 영어·미등록어는 빈칸으로 지우지 않고 수정 대상 표시.
- [ ] 변환 실패 줄도 원문이 남고 편집 가능한 상태로 반환.

통과 예제는 조사의 は와 일반 음절 は, きゃ, っ, ん, ー, 한자 복수 읽기, 영어 혼용, 숫자, 구두점을 포함한다. 기대 독음은 제품 규칙으로 명시하며 실제 일본어 발음을 완벽히 대체한다고 주장하지 않는다.

### T05 — 실제 E2E와 캐시 (8~10h)

의존: T01~T04.

- [ ] 업로드→정규화→분리→정렬→독음→검증→재생 연결.
- [ ] 경계 offset·음원 길이 검증. 모델용 resample을 재생 음원과 혼동하지 않음.
- [ ] 가사와 모델 설정을 포함한 결과 키, 오디오 기준 분리 키.
- [ ] 같은 입력 재시도에서 검증된 분리 결과 재사용.
- [ ] 캐시 결과임을 내부 실행 기록에서 구분.
- [ ] 미정렬은 needs_review, 분리 실패는 failed로 표시.

반자동 모드에서는 MR·독음 생성 후 경계 null 결과를 반환하고 T06으로 연결한다. 가짜 타임스탬프로 ready를 만들지 않는다.

### T05-K — 키 조절과 프리셋 (10~12h)

의존: T01 pitch 엔진 검증, T02 variant 계약, T03 재생 시계, T05 기준 MR.

- [ ] -5..+5 정수 반음, tempo 1·pitch 비율 `2^(n/12)`로 기준 MR에서 렌더.
- [ ] 남성/원키/여성 기본 -5/0/+5와 설정 가능한 프리셋, 최종 절대값 표시.
- [ ] 같은 프리셋 재클릭은 누적하지 않음. fine tune·범위 끝 버튼 동작.
- [ ] 요청값·적용값 분리, 준비 중 상태·취소·마지막 요청 우선 반영.
- [ ] 현재 위치·재생 의사 보존 후 자산 교체, 실패 시 기존 음원 복구.
- [ ] 기준 MR 해시·키·출력·엔진/프로필 버전으로 캐시. 분리·정렬 재실행 없음.
- [ ] 시작/중간/끝 경계 오차 목표 ±50ms, drift·템포 변화가 없는지 실제 측정.
- [ ] 원키·프리셋·미세 조절을 실제로 들어보고 변환 흔적 기록.

새 렌더링과 캐시 hit의 대기 시간을 분리해 기록한다. 서버 렌더링이 필요한데 “즉시 무중단 전환”이라고 표시하지 않는다. 렌더 실패를 원키 적용 성공으로 바꿔 표시하지 않는다.

### T05-M — 출력·가사 모드와 실제 사용 검증 (12~13h)

- [ ] original/phone 변형을 같은 variant 상태·전환 절차로 연결.
- [ ] Phone: 저역 정리·중역 보정·압축·mono 호환·limiter, 실제 폰에서 값 결정.
- [ ] 같은 청감 볼륨에서 Original과 비교하고 클리핑·악기 소실·지연 확인.
- [ ] 출력 모드는 음색 선택임을 표시. 하드웨어 장치를 바꾸었다고 표시하지 않음.
- [ ] 웹에서 WAV를 틀고 스피커 옆에 독립 노래방 마이크를 두어 반주·목소리를 청취.
- [ ] 마이크 입력·권한·상태 UI 없이 Phone/Original 출력만 선택 가능.
- [ ] 가사 모드 전환으로 재생·키·출력이 바뀌지 않음.

이 시간 예산은 엄격하다. 기본 API/재생 상태는 T02/T03에서 먼저 만들어 두고 여기서는 연결·청취 검증에 집중한다. 부족하면 미완료 항목과 추가 필요 시간을 기록한다.

### T06 — 수정과 다시 쓰기 (13~14h)

- [ ] 원곡 미리듣기와 MR 동시 재생 방지.
- [ ] 줄 시작·끝 입력/현재 위치 찍기, 한글 독음 수정.
- [ ] 전체 표시 오프셋과 개별 타임스탬프의 의미 분리.
- [ ] 수정된 줄의 기존 상세 그룹 제거, 줄 수준으로 하향.
- [ ] PATCH 유효성 검사, revision 충돌 시 최신본 다시 열기 안내.
- [ ] 새로고침 후 수정 유지, 최근 목록에서 재생.
- [ ] 성공한 키·프리셋·출력·가사 모드 복원.

## 5. 검증표

문서 변경만 한 현재 단계에서는 애플리케이션 테스트 통과를 주장하지 않는다. 아래는 구현 시 확인할 항목이다.

### 자동화할 가치가 있는 검증

| 영역 | 사례 | 기대 결과 |
|---|---|---|
| 결과 계약 | 음수·역전·곡 밖 경계 | 저장 거절 또는 명시적 미정렬 처리 |
| 반복 가사 | 같은 문장 두 번 | 다른 ID와 올바른 시간 순서 |
| null 타이밍 | 정렬 실패 줄 | 재생 계산 오류 없이 수정 목록 표시 |
| 독음 | 조사/일반 は, 요음·촉음·장음 | 고정한 제품 규칙과 일치 |
| 원문 매핑 | 한자↔복수 kana, 비BMP 문자 | 코드포인트 범위 보존 |
| 수정 | 세부 그룹이 있는 줄의 독음 변경 | 그룹 제거·line 수준 전환 |
| 캐시 | 같은 음원, 다른 가사 | 분리 재사용, 결과 키 변경 |
| 작업 복구 | worker 중단/재시작 | 무한 running 없이 실패·재시도 가능 |
| 파일 입력 | 잘못된 확장자·손상 파일·길이 초과 | 추론 전 거절 |
| revision | 오래된 수정본 저장 | 충돌 반환, 최신본 덮어쓰지 않음 |
| 키 값·프리셋 | -5/+5, 범위 밖, 반복 클릭 | 범위 검증·절대값·누적 방지 |
| 렌더 정확성 | 알려진 테스트음·transient·여러 길이 | `2^(n/12)` 비율, tempo 보존·경계 오차 측정 |
| 변형 캐시 | 같은 MR/키/출력, 다른 가사 | 재사용; 키나 프로필 버전 변경 시 새 렌더 |
| 비동기 전환 | -5→+2 요청 중 -5 늦게 완료 | 마지막 요청만 적용·저장 |
| 렌더 실패 | 엔진 실패·타임아웃·자산 로드 실패 | 기존 키·출력·재생 위치로 복구 |

### 사람이 확인할 필수 동작

- [ ] 재생을 10초 멈춘 뒤 재개해도 가사가 10초 앞서가지 않는다.
- [ ] 중간으로 탐색하고 다시 뒤로 가도 현재·다음 줄이 맞는다.
- [ ] 간주가 길어도 직전 줄이 활성 상태로 남지 않는다.
- [ ] +0.2초 오프셋이 실제로 가사를 늦춘다.
- [ ] 시작/끝을 고친 뒤 새로고침해도 수정이 남는다.
- [ ] 원곡 미리듣기를 시작하면 MR이 멈춘다.
- [ ] 모바일 세로 화면에서 한글·버튼·진행 바가 겹치지 않는다.
- [ ] MR의 잔류 보컬·악기 손상·클리핑을 실제로 들어본다.
- [ ] 자동 결과·수동 보정·캐시 시연이 발표에서 구분된다.
- [ ] 남성 -5→미세 조절 -4→원키 0에서 템포·가사 싱크가 유지된다.
- [ ] 재생 중·일시정지 중 키/출력 변경이 이전 재생 의사를 유지한다.
- [ ] 키를 연달아 누른 뒤 표시 값과 들리는 음정이 일치한다.
- [ ] Phone 전환 후 실제 폰에서 클리핑·급격한 음량 증가·위상 상쇄가 없는지 듣는다.
- [ ] 가사 3가지 모드가 오디오를 멈추지 않고 바뀐다.
- [ ] 어떤 재생·모드 전환에서도 마이크 권한을 요청하지 않는다.
- [ ] 폰/PC와 연결하지 않은 노래방 마이크를 스피커 옆에 두고 반주·목소리가 함께 들리는지 확인한다.

P1 guide를 추가했다면 재생·정지·앞뒤 탐색 반복 후 두 트랙이 함께 움직이는지 따로 검증한다. 통과하지 못하면 시연에서 기능을 끈다.
