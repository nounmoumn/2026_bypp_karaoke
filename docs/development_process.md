# BYPP 개발 과정 기록

> 개인용 "즉석 노래방" 웹 서비스 — 음원 + 가사만 넣으면 MR·동기화된 가사 화면·키 변환을 자동으로 만든다.
> 이 문서는 실제로 진행한 순서, 막힌 지점과 해결, 측정 결과를 정리한 것이다. 세부 수치의 원본은 `docs/poc_results.md`.

## 1. 문제 정의

- 부르고 싶은 곡(주로 J-pop, 이후 한국 곡 추가)이 노래방에 없다.
- 있어도 일본어 가사를 읽을 수 없어 부르기 어렵다.
- 목표: 음원 파일과 가사 텍스트를 넣으면 **MR 분리 → 줄/글자 단위 타이밍 → 한글 독음 → 내 음역에 맞는 키 → 노래방 화면**까지 자동으로 만든다. 사용자는 나 혼자(개인용).

## 2. 시스템 구성

```
음원 + 가사
   │  Demucs (htdemucs) ── 보컬 / MR 분리
   │  WhisperX(wav2vec2 CTC) ── 가사 강제 정렬 (줄·글자 시각)
   │  일본어 독음 변환 / 한국어는 직접 정렬
   │  F0 추출 → 원곡 성별 판정 + 가이드 멜로디
   │  ffmpeg rubberband ── MR 키 변환 (남/여 프리셋, 선택적 ±6 반음)
   ▼
karaoke.json + MR + 가이드 → FastAPI 백엔드 → 웹 플레이어(2줄 가사, 키 선택, 가이드음)
```

- 무거운 단계(분리·정렬)는 RunPod GPU(RTX PRO 4000)에서 실행, 웹 앱도 같은 Pod에 배포.
- 코드: `scripts/`(파이프라인), `backend/`(FastAPI), `frontend/`, `docs/`.

## 3. 개발 타임라인

### 3.1 기획과 위험 우선 검증 (T01)
- 기획서 v3와 18시간 기준 구현 계획을 먼저 작성. 가장 위험한 부분인 **노래의 자동 시간 정렬**을 첫 단계(T01)에서 검증하도록 순서를 잡았다.
- 환경 확인(CPU 전용 노트북), FFmpeg rubberband 키 변환 스모크 테스트: ±5반음에서 주파수 오차 1 Hz 이내, 길이 오차 0 ms.
- Demucs로 실제 곡 분리, ASR·강제 정렬 시험. 첫 곡(晩餐歌)에서 자동 결과가 겹치거나 순서가 뒤집히는 줄이 나옴 → 방법 개선(가사를 이어 붙여 한 번에 정렬 후 글자 위치로 줄 분할)으로 역전·겹침 0건.

### 3.2 정량 게이트 평가
- 3곡(43줄)을 사람이 듣고 기준 시각을 만든 뒤 자동 결과와 비교.
- 합계: 유효 줄 100%, 시작 ±0.5초 97.7%, 끝 ±0.7초 86.0% — 합계 목표(90/80/80%)는 통과.
- 그러나 곡별로는 끝 시각이 두 곡에서 목표 미달(75.0%, 76.9%). **판정: 반자동(mixed) 모드** — 시작은 자동, 끝은 사람이 확인할 수 있게 검수 화면 제공. 통과 범위와 미보증 범위(발라드, 랩, 다인 보컬)를 기록으로 남김.
- 이 평가 과정에서 검수자에게 자동 후보를 보여준 점(완전한 블라인드가 아님)도 한계로 명시.

### 3.3 자동 파이프라인과 GPU 이전
- 새 곡을 사람 개입 없이 처리하는 공통 파이프라인 구성. 새 곡(一輪花, 225초)으로 검증: **GPU 처리 24.9초**(분리+정렬+검수), CPU 대비 약 10배 이상 빠름. 54/54줄 정렬, 역행 0, 무음 중간 시작 0.
- 검증 중 **가사 텍스트가 곡 끝 22.8초 분량을 누락**한 것을 `unmatched_vocal_activity` 플래그가 감지. 억지로 채우지 않고 이웃 줄이 밀리지 않게 격리 — "정렬기의 한계가 아니라 가사 출처의 한계"임을 스펙트럼 상관·자기상관 등으로 확인.

### 3.4 사용성 개선 (UX)
- 2줄 동시 표시(윗줄이 끝나면 두 줄이 함께 전환), 가이드 멜로디(색소폰 음색), 남/여 전환 버튼 하나로 통일(원곡 성별 ↔ 반대 음역), 스크롤형 키 선택기, 폰·태블릿 가로 화면 우선.
- 원곡 성별은 F0 분석(임계 200 Hz)으로 자동 판정, 기본 프리셋은 원키 + 성별 반대 키 두 개만 렌더.

### 3.5 정적 HTML → 웹 서비스
- 폰에서 정적 HTML을 열면 영상·음원이 재생되지 않는 문제 발견 → FastAPI 백엔드 + 템플릿 기반 통합 웹 서비스로 전환(HTTP Range/206 스트리밍 포함).
- 곡 등록 화면(`/new`): 음원 파일 업로드(wav/mp3/mp4) + 가사 + 언어 선택. 반음 단위 전체 키 렌더는 시간이 오래 걸려 **선택 옵션**으로 분리(기본은 남/여 두 키만).
- 동일 음원 재등록 방지(중복 감지 = 캐시 강화).

### 3.6 막힌 지점과 결정
| 문제 | 원인 | 결정 |
|---|---|---|
| 유튜브 링크 자동 다운로드 실패 | 데이터센터 IP에 대한 봇 차단, CDN URL은 IP 서명, OAuth 플러그인 중단 | 개인용이므로 로컬 다운로드/파일 업로드 방식으로 전환(쿠키·계정 우회는 하지 않음) |
| 작업 실행 중 오류(포트가 int로 전달) | 외부 수정된 설정 타입 불일치 | `str()` 변환 |
| 자식 프로세스 한글 출력 오류(cp949) | Windows 기본 인코딩 | `PYTHONIOENCODING=utf-8` 지정 |
| SSH 다중화 실패 | Pod 프록시 미지원 | 원복, 단순 SSH/SCP 유지 |
| 키 선택기 초기 위치 어긋남 | smooth-scroll과 snap 경합 | 초기 위치는 즉시 이동 + 프로그램 스크롤 가드 |

### 3.7 한국어 엔진 고도화 (밀림/끌림 수정)
- 한국 곡 3곡(blueming, minjok_aria, single)에서 가사가 소리보다 앞서거나(밀림) 늦는(끌림) 현상.
- 정답 시각이 없으므로 **보컬 스템 자체를 기준으로 한 무라벨 지표**(줄 구간과 실제 노래 프레임의 겹침 F1, 무음인데 켜진 줄, 놓친 노래 시간 등)를 만들어 진단.
- 원인: (1) 원곡 믹스로 정렬하면 노래 없는 구간에 줄이 켜짐, (2) 음성용 정렬 모델이 길게 끄는 음의 꼬리를 앞뒤 줄로 넘김.
- 해결(`scripts/korean_engine.py`, 옵트인 `--ko-engine v3`): 믹스/스템 두 번 정렬 후 겹침이 큰 쪽 선택 → 뚜렷한 쉼에 줄 경계 맞춤 → 이어지는 노래 구간만큼 줄 연장/시작 당김 → 가사 없는 노래 구간은 보고만 함. **기존 엔진·일본어 경로는 수정하지 않고** 별도 모듈로 분리해 시연 안정성 확보.
- 결과: single F1 0.730→0.865, 무음 켜진 줄 12→3, 놓친 노래 54.9→18.9초 / minjok_aria 0.904→0.912, 시작 오차 중앙값 0.15→0초 / blueming 변화 없음(이미 양호).
- 한계: 같은 스템으로 측정한 근사 지표라 일부 순환적이며, 한국어 정답 기준은 없음. 사람 귀 확인 필요.

## 4. 작업 방식 (AI 협업)
- 설계·요구 정의·판단·청취 검수는 사람(나)이, 구현과 실험 실행은 AI 코딩 에이전트가 맡았다. 중간에 이전 에이전트(Codex)가 중단되어 다른 에이전트(Claude)가 문서와 코드를 읽고 작업을 이어받았다.
- 인수인계가 가능했던 이유: 결정·측정·한계를 `docs/`에 계속 기록했기 때문. 평가 기준과 실패 사례도 그대로 남겼다.
- 원칙: 시연에 쓰는 원본 경로는 건드리지 않고 실험은 별도 디렉터리/옵트인 플래그로 분리, 측정 없이 "좋아졌다"고 쓰지 않기, 저작권 있는 음원·가사는 저장소에서 제외(`data/`는 `.gitignore`).

## 5. 배운 점
1. 가장 위험한 것(정렬 정확도)을 먼저 정량 평가한 덕분에 "완전 자동" 대신 "반자동"으로 현실적인 범위를 정할 수 있었다.
2. 합계 지표는 곡별 실패를 가릴 수 있다 — 곡 단위 결과를 함께 봐야 한다.
3. 정렬 실패의 상당수는 알고리즘이 아니라 입력(가사 누락, 반주가 큰 믹스)에서 왔다. 감지하고 격리하는 것이 억지로 채우는 것보다 낫다.
4. 정답이 없을 때는 신호 자체(보컬 스템)로 검증 가능한 대리 지표를 만들되, 그 한계를 함께 적는다.

## 6. 현재 상태와 남은 일
- 일본어 곡: 공통 파이프라인으로 새 곡 자동 처리 확인. 끝 시각은 반자동 검수 권장.
- 한국어 곡: v3 엔진이 옵트인으로 준비됨(로컬에서 v2/v3 비교 청취 가능). 청취 검증 후 기본값 여부 결정.
- 서비스: Pod에 배포(v2 기준). v3 배포는 청취 확인 후.
- 남은 일: 한국어 청취 검수, 느린 발라드·랩·다인 보컬 성능 검증, 폰+노래방 마이크 실사용 시연 점검.
