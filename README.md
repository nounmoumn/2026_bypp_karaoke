# BYPP — Instant J-Pop Karaoke

**노래방에 없는 최애곡, 내가 읽을 수 있는 가사로 부르기.**

> 2026.09 · 개인 프로젝트 · **완료**
> `Python` `FastAPI` `Demucs` `faster-whisper` `WhisperX(wav2vec2)` `FFmpeg rubberband` `RunPod GPU`

음원과 가사를 넣으면 MR, 한글 독음, 줄·글자 단위로 맞춘 가사 화면, 내 음역에 맞춘 키까지 만들어 주는 개인용 웹 노래방입니다.
반주는 폰이나 PC 스피커로 틀고, 노래방 마이크는 그 옆에 따로 두고 부르는 방식입니다.

## 파이프라인

```
음원 + 가사
   │  Demucs (htdemucs) ─────────── 보컬 / MR 분리
   │  faster-whisper ───────────── 대략적인 가사 구간 인식
   │  WhisperX (wav2vec2 CTC) ──── 줄·글자 단위 강제 정렬
   │  일본어 독음 변환 / 한국어는 직접 정렬
   │  F0 추출 ───────────────────── 원곡 성별 판정 + 가이드 멜로디
   │  FFmpeg rubberband ────────── MR 키 변환 (남/여 프리셋, 선택적 반음 단위)
   ▼
karaoke.json + MR + 가이드 → FastAPI 백엔드 → 웹 플레이어
```

무거운 단계(분리, 정렬)는 RunPod GPU에서 실행합니다. 225초 곡 기준 GPU 처리 약 25초입니다.

## 정렬 정확도 평가

세 곡 43줄의 가사 시작·끝 시각을 직접 듣고 찍어 기준을 만든 뒤, 사전 자료 없이 완전 자동으로 만든 결과와 비교했습니다.

| 곡 | 줄 | 시작 ±0.5초 | 끝 ±0.7초 |
|---|---:|---:|---:|
| 晩餐歌 | 18 | 100% | 100% |
| 月面着陸計画 | 12 | 91.7% | 75.0% |
| 星街の駅で | 13 | 100% | 76.9% |
| **합계** | 43 | **97.7%** | **86.0%** |

합계로는 목표(80%)를 넘었지만, 곡별로 보면 두 곡의 끝 시각이 목표에 못 미쳤습니다. 말소리로 학습된 정렬 모델이 노래에서 길게 끄는 음을 일찍 잘라 버리는 것이 주된 원인이었습니다.
그래서 **시작 시각은 자동, 끝 시각은 검수 화면에서 한 번 듣고 고치는 반자동 방식**으로 정했습니다.

한국어 곡은 정답 시각이 없어서, 분리한 보컬에서 실제로 노래하는 구간과 가사 줄이 얼마나 겹치는지를 대리 지표로 만들어 진단했습니다. 보컬의 실제 쉼에 줄 경계를 맞추는 보정(`--ko-engine v3`, 선택 옵션)으로 한 곡의 겹침 F1이 0.730에서 0.865로 올랐습니다. 같은 보컬로 만든 지표라 한계가 있어 기본값으로는 켜지 않았습니다.

자세한 수치와 판단 과정은 [`docs/poc_results.md`](docs/poc_results.md), 전체 개발 과정은 [`docs/development_process.md`](docs/development_process.md)에 있습니다.

## 완료 범위와 한계

- 일본어 곡: 새 곡을 업로드하면 공통 파이프라인으로 자동 처리됩니다. 끝 시각은 검수를 권장합니다.
- 한국어 곡: 기본 엔진으로 처리되고, 보정 엔진은 선택 옵션으로 남겨 두었습니다.
- 웹: 곡 등록(파일 업로드 + 가사), 2줄 가사 표시, 가이드 멜로디, 남/여 키 전환, 반음 단위 키 선택을 지원합니다.
- 유튜브 링크 자동 다운로드는 서버 IP 차단 때문에 넣지 않았고, 파일 업로드 방식만 지원합니다.
- 느린 발라드, 랩, 여러 명이 부르는 곡의 정렬 성능은 검증하지 않았습니다.
- 저작권 때문에 음원과 가사 데이터는 저장소에 포함하지 않습니다.
